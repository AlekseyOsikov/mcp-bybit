# mcp-server-runtime Specification

## Purpose

Определяет, как MCP-сервер `mcp-bybit` регистрирует инструменты, описывает их параметры, возвращает результаты и ошибки и как запускается и проверяется клиентом. Это контракт между сервером и внешним ИИ-агентом.

## Requirements

### Requirement: Регистрация инструментов
Сервер SHALL публиковать через `list_tools` ровно шесть инструментов: `search_symbols`, `get_current_price`, `get_price_history`, `compute_price_metrics`, `compare_with_benchmark` и `compare_securities`. Каждый инструмент MUST иметь текстовое описание, объясняющее для чего он нужен и когда его применять, и JSON-схему входных параметров с типами, описаниями, допустимыми значениями перечислений, значениями по умолчанию и границами. Все шесть инструментов MUST быть помечены как только читающие (`readOnlyHint = true`). Сервер SHALL NOT публиковать инструменты, изменяющие внешние системы, торговые счета или требующие API-ключей.

#### Scenario: Клиент запрашивает список инструментов
- **WHEN** клиент вызывает `list_tools`
- **THEN** ответ содержит ровно шесть инструментов с именами `search_symbols`, `get_current_price`, `get_price_history`, `compute_price_metrics`, `compare_with_benchmark`, `compare_securities`
- **AND** у каждого есть описание и `inputSchema` с описанием каждого параметра
- **AND** у каждого установлен признак `readOnlyHint = true`

#### Scenario: Описание подсказывает порядок использования
- **WHEN** агент читает описания инструментов
- **THEN** описания `get_current_price` и `get_price_history` указывают, что тикер (`symbol`) следует получать через `search_symbols`, если пользователь назвал монету, а не точный тикер пары
- **AND** описания `compute_price_metrics`, `compare_with_benchmark` и `compare_securities` указывают, что историю следует получать через `get_price_history`

### Requirement: Формат результата инструмента
Успешный вызов инструмента SHALL возвращать структурированный результат (`structuredContent`), соответствующий выходной JSON-схеме инструмента, и дублировать его текстовым JSON в `content` для клиентов без поддержки структурированного вывода. Все поля результата MUST иметь понятные имена и явные единицы измерения; сырой ответ Bybit (обёртка `retCode`/`retMsg`/`result`) SHALL NOT попадать в результат как есть.

#### Scenario: Успешный вызов
- **WHEN** клиент вызывает любой из инструментов с корректными аргументами
- **THEN** результат не помечен как ошибка
- **AND** содержит `structuredContent`, соответствующий схеме
- **AND** текстовый `content` содержит тот же JSON

### Requirement: Ошибки инструмента
Сервер SHALL сообщать об ошибках как о результате инструмента, помеченном как ошибка (`isError = true`), с понятным для LLM текстом: что произошло и что делать дальше. Сервер MUST NOT завершаться аварийно и MUST NOT раскрывать в тексте ошибки внутренние трассировки или сырой `retCode` без пояснения. Ошибки SHALL охватывать как минимум: неизвестный или неторгуемый символ, запрос по неподдерживаемой категории инструмента (не `spot`), некорректные аргументы, недоступность Bybit (таймаут, сетевая ошибка, HTTP-ответ не 2xx, `retCode != 0`), слишком большой запрошенный объём данных.

#### Scenario: Bybit недоступен
- **WHEN** Bybit не отвечает или отвечает ошибкой после исчерпания повторов
- **THEN** вызов любого инструмента, обращающегося к бирже, завершается результатом с `isError = true`
- **AND** текст ошибки говорит о недоступности биржи, а не содержит трассировку

#### Scenario: Неизвестный символ
- **WHEN** клиент вызывает `get_current_price` или `get_price_history` с символом, которого нет среди торгуемых спотовых пар Bybit
- **THEN** вызов завершается ошибкой, в тексте которой назван символ и сказано, что пару стоит поискать через `search_symbols`

### Requirement: Запуск сервера
Сервер SHALL по умолчанию работать по транспорту `stdio` и SHALL поддерживать запуск по Streamable HTTP только на `127.0.0.1` через явный параметр командной строки для отладки. Журналирование SHALL идти в stderr; при транспорте `stdio` в stdout MUST попадать только протокол MCP.

#### Scenario: Запуск по умолчанию
- **WHEN** сервер запускается без параметров транспорта
- **THEN** он работает по `stdio` и в stdout не попадает ничего, кроме сообщений протокола MCP

#### Scenario: Запуск для отладки
- **WHEN** сервер запускается с параметром `--transport streamable-http`
- **THEN** он слушает только `127.0.0.1` на указанном порту
