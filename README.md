# mcp-bybit

MCP-сервер над публичным v5 API биржи Bybit (только спотовый рынок, `category = spot`). Даёт ИИ-агенту поиск торговых пар, текущую цену и историю цен, а также расчёт метрик по истории и сравнение пар. Ключи и регистрация не нужны, сервер работает локально и не публикует никаких торговых или аккаунтных инструментов.

## Инструменты

Инструментов шесть, и все только читают данные (`readOnlyHint`): три с данными биржи и три анализа уже полученной истории. Схемы параметров и подробные описания сервер отдаёт клиенту через `list_tools`.

| Инструмент | Для чего | Параметры |
|---|---|---|
| `search_symbols` | Найти спотовую пару по монете или части тикера | `query`; `limit`: 1–20 (по умолчанию 10) |
| `get_current_price` | Актуальная цена пары в реальном времени | `symbol` (тикер, регистр не важен) |
| `get_price_history` | Свечи за период и готовая сводка | `symbol`; `date_from` (`YYYY-MM-DD`); `date_till` (по умолчанию сегодня UTC); `interval`: `15m`, `1h`, `4h`, `1d` (по умолчанию), `1w`, `1M` |
| `compute_price_metrics` | Метрики одной пары: изменение цены, годовая волатильность, максимальная и текущая просадка, изменение по каждой свече | `history` (результат `get_price_history`) |
| `compare_with_benchmark` | Пара против эталона (например BTCUSDT): изменение обоих, разница в п. п., бета, корреляция, просадки, таблица по периодам | `history` (пара), `benchmark_history` (эталон) |
| `compare_securities` | Две пары между собой: изменение обеих, разница A минус B в п. п., корреляция, просадки, таблица по периодам | `history_a`, `history_b` |

Обычный порядок для агента: пользователь назвал монету словами, значит `search_symbols`, затем `get_current_price` или `get_price_history` с найденным `symbol`. Чтобы посчитать метрики или сравнить пары, результаты `get_price_history` передают в инструменты анализа.

## Анализ истории

Три инструмента анализа считают по истории, которую агент уже получил от `get_price_history`: без обращений к бирже, без файлов и без состояния между вызовами. Считает код сервера, а не модель, поэтому числа проверяемы.

- **Вход.** Параметры `history`, `benchmark_history`, `history_a`, `history_b` принимают результат `get_price_history` **целиком и без изменений**. Сервер проверяет вход: история не усечена (`candles_truncated = false`, для длинных периодов берите `interval = "1w"` или `"1M"`), `interval` это `1d`, `1w` или `1M` (внутридневные `15m`/`1h`/`4h` анализ не поддерживает), свечи согласованы со `summary`, цены положительны.
- **Согласованность монеты.** `compare_with_benchmark` и `compare_securities` требуют, чтобы у обеих историй совпадала котируемая монета (`price_unit`, она же `quote_coin`): сравнивать `BTCUSDT` с `ETHBTC` напрямую нельзя (разные валюты цены), вызов завершится ошибкой, называющей обе монеты.
- **Что считается.** Изменение цены за период совпадает со `summary.change_pct`: первая свеча от `open`, остальные от `close` предыдущей. Волатильность: стандартное отклонение изменений между соседними закрытиями, приведённое к году (`annualization_factor`: 365 для `1d` — крипта торгуется 24/7, 52 для `1w`, 12 для `1M`). Просадки по закрытиям. Сравнения идут по общим `begin` двух историй, `interval` обеих должен совпадать. Корреляция и бета (только у `compare_with_benchmark`) считаются по изменениям между соседними закрытиями и равны `null` при малой выборке или нулевом разбросе.
- **Результат** содержит числа, `periods` (по одному элементу на свечу, у последней `partial = true`, если период не завершён), `notes` (предупреждения) и готовый шаблонный русский `text` без LLM: его можно отправлять пользователю как есть.
- **Это изменение цены, а не доходность.** Комиссии биржи, вознаграждения, эйрдропы и стейкинг не учитываются; в `notes` всегда есть эта оговорка. Эталон в `compare_with_benchmark` (например `BTCUSDT`) сам является рискованным активом, а не безрисковым индексом. При резком скачке ликвидности (закрытие изменилось в 1,8 раза и более между соседними свечами) в `notes` есть предупреждение, что метрики могут быть искажены.

## Формат результатов

Успешный вызов возвращает `structuredContent` (по схеме инструмента) и тот же JSON текстом в `content`. Поля названы понятно, конверт Bybit (`retCode`/`retMsg`/`result`) наружу не попадает.

**Единицы цен** (`price_unit`) — это котируемая монета пары (`quote_coin`): `USDT` для `BTCUSDT`, `USDC` для пар к USDC, `BTC` для `ETHBTC` и так далее. Никакого пересчёта в другую валюту не делается.

**Реальное время.** В отличие от бирж с задержкой данных, у Bybit нет искусственной задержки котировок: `get_current_price` отдаёт цену последней сделки, `as_of` — это время формирования ответа биржей.

**История.** В `summary` считаются по всем свечам периода: начало, конец, минимум, максимум и изменение в %. В `candles` приходят не более 300 последних свечей (`candles_truncated`). Слишком большой запрос (больше 5000 свечей на выбранном интервале) даёт ошибку с советом выбрать более крупный `interval`.

**Ошибки** приходят как результат инструмента с `isError = true` и понятным текстом: что случилось и что делать (неизвестный тикер, тикер существует только среди деривативов, неверные аргументы, Bybit недоступен, слишком большой период).

## Ограничения

- Только спотовый рынок (`category = spot`). Деривативы (linear, inverse, option) — funding rate, open interest, маржинальная торговля — не поддерживаются.
- Только публичные рыночные данные. Приватные эндпоинты (баланс аккаунта, размещение ордеров) не поддерживаются и не требуют ключей API.
- Стакан (order book) и лента последних сделок не поддерживаются.
- Режима расписания (периодический опрос цен для чат-бота) нет.
- Анализ считает только изменение цены: комиссии, вознаграждения, эйрдропы и стейкинг не учитываются, оценка доходности держателя не делается.
- Клиент Bybit не использует прокси из окружения.

## Запуск

По умолчанию сервер работает по `stdio`: клиент сам запускает его как подпроцесс.

```bash
uv run --directory /media/alexey/DATA/Projects/Python/mcp-bybit mcp-bybit
```

Для отладки можно запустить его по Streamable HTTP, только на `127.0.0.1`:

```bash
uv run mcp-bybit --transport streamable-http --port 8000   # http://127.0.0.1:8000/mcp
```

Журнал пишется в stderr; при `stdio` в stdout идёт только протокол.

## Подключение из проекта агента

Пример на MCP SDK для Python; работает с `mcp` 1.x и 2.x (проверено на 2.2).

```python
import asyncio
import json

from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

MCP_BYBIT_DIR = "/media/alexey/DATA/Projects/Python/mcp-bybit"


async def main() -> None:
    server = StdioServerParameters(command="uv", args=["run", "--directory", MCP_BYBIT_DIR, "mcp-bybit"])
    async with stdio_client(server) as (read, write):
        async with ClientSession(read, write) as session:
            await session.initialize()

            # Описания и схемы параметров для LLM: name, description, inputSchema (в mcp 2.x input_schema).
            tools = await session.list_tools()
            print([tool.name for tool in tools.tools])

            found = await session.call_tool("search_symbols", {"query": "BTC"})
            symbol = json.loads(found.content[0].text)["results"][0]["symbol"]

            price = await session.call_tool("get_current_price", {"symbol": symbol})
            print(json.loads(price.content[0].text))  # либо price.structuredContent (в mcp 2.x structured_content)


asyncio.run(main())
```

## Разработка

- Тесты работают только на записанных ответах Bybit в `tests/fixtures/`; сетевые соединения в них запрещены. Записать недостающие: `RECORD_FIXTURES=1 uv run pytest`.
- Спецификации поведения лежат в `openspec/specs/`; дизайн и решения первой реализации в `openspec/changes/archive/` (после архивации изменения `add-bybit-spot-mcp-server`).
